## playRaw bit-depth decision

Upstream M5Unified's `Speaker_Class` ships **three** `playRaw` overloads —
verified against the canonical header:

```cpp
bool playRaw(const int8_t*  raw, size_t, uint32_t sr, bool stereo=false, ...);  // signed 8-bit
bool playRaw(const uint8_t* raw, size_t, uint32_t sr, bool stereo=false, ...);  // unsigned 8-bit
bool playRaw(const int16_t* raw, size_t, uint32_t sr, bool stereo=false, ...);  // signed 16-bit
```

**Decision: 16-bit signed (int16_t) at 16 kHz mono.** The brief flagged `int8_t`
playback as a possibility, but the int16_t overload exists and the firmware
asks the Speaker to DMA the buffer directly, so keeping the waveform at full
16-bit fidelity is free at this sample rate. `audio_clips.cpp` passes the data
pointer unchanged — no runtime conversion, no quality loss.

`audio_clips_data.h` therefore contains:

* six `static const int16_t kClipPcm_X[] CLIP_PROGMEM = { ... };` arrays
* six `static const size_t kClipSamples_X = N;` counters
* a `#define CLIP_TABLE_INIT { ... }` macro used by `audio_clips.cpp`

`CLIP_PROGMEM` is an empty macro by default; the Arduino/ESP build defines it
to `PROGMEM` automatically when `<pgmspace.h>` is reachable. .rodata already
lives in flash on ESP32, so the attribute is informational on real hardware —
it only matters for the standalone validator and for future AVR-style rebuilds.

The four `beep(...)` calls remaining elsewhere in `main.cpp` (menus, settings,

keeps every existing chip-level audio path alive.

## Protocol round-trip

```
bridge.ts                                  firmware/data.h + main.cpp
─────────────────                          ───────────────────────────
turn/end (within 8s merge)          
  → completionSeq++                  →   completion_seq on wire  → completionChimeObserve
                                                                       (data.h:293-298)
                                                                       → playCompletionSound()
                                                                       
tool/result.error truthy              
  → errorSeq++                       →   error_seq on wire       → errorSeqState observer
                                                                       (main.cpp:2284-2291)
                                                                       → playClip(Clip::Error)
                                                                       
flush, every 60s (config.timeSyncIntervalMs)
  → time: [epoch_sec, tz_off]        →   time array on wire      → existing parser
                                                                       (data.h:250-279,
                                                                        epochInRange check)
```

## Notes for the acceptor

* `audio_clips.cpp` uses `__has_include(<M5Unified.h>)` so the validator
  command above works on a vanilla VM. Real PlatformIO pulls in M5Unified via
  `board_compat.h`, and the `#endif` branch is taken on actual builds.
* The FR2 character pack (P2 character branch) is the right place to wire the
  `triggerOneShot(P_DIZZY, ...)` call that goes with `playClip(Error)`. The
  brief explicitly carved animation out of this PR; the `// AC-P2-2 animation
  hook goes here — owned by the character branch` comment in main.cpp marks
  the spot.
* `beep(2400/600, 60)` on the four approval/deny paths is replaced, not
  removed. A future "voice pack missing" guard could fall back to the
  existing chip-level chime; the brief explicitly recommends keeping this
  safety net.
